# Contributing to DataLoom

Thank you for your interest in contributing to DataLoom.

## Contribution requirements

- Each pull request must be scoped to **one approved issue**.
- Use a focused branch for a single feature or fix (for example,
  `feature/DL-002-short-description` or `fix/DL-101-short-description`).
- Production-code changes must include appropriate tests.
- Public API changes must include documentation updates.
- Changes that affect module boundaries or public API design require
  architecture approval before merge.
- Never include credentials or secrets in code, commits, issues, examples,
  tests, prompts, or logs.
- All pull requests must remain open for **human review** before merging.
- Publishing packages or creating releases requires **human approval**.

## Development scope (foundation stage)

During foundation-stage issues, avoid introducing production SDK code,
Gradle project setup, Android configuration, CI/CD workflows, publishing
configuration, or release automation unless explicitly required by an approved
issue.
