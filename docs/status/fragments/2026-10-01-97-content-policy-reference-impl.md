## (a) Proposed "Recently shipped" row

| 2026-10-01 | `#97`: a concrete reference scanner/quarantine-store implementation of `AssetContentPolicy` (the follow-up `#463`'s own fragment named as deferred), plus docs. New `io.dataloom.assets.policy` package: `HashDenyListAssetContentPolicy` is a real, usable `AssetContentPolicy` that hashes each chunk it is given (configurable digest algorithm, default SHA-256) and looks it up in a configured deny list of known-bad digests -- an exact-match hash-blocklist technique genuinely used in production content-blocking systems, not a toy. It checks only the chunk it is actually given, never attempting a whole-object decision: `AssetContentPolicyContext` carries no "last chunk" or chunk-count signal, so a whole-object exact-hash check cannot honestly be implemented inside one `evaluate` call without the engine supplying that signal (it does not); this is a deliberate, documented scope decision, not an oversight. `DurableAssetContentQuarantineLog` is a durable quarantine store a `Quarantine`-action match is recorded to before the decision is returned, mirroring `DurableConflictQuarantineLog`'s own CAS-log-over-`DurableStateStore` pattern exactly (read directly as the structural precedent, per this slice's own instructions): per-`AssetTransferSessionId` records (asset id/version, chunk index, reason code, matched digest hex, timestamp -- never chunk bytes), a bounded load-evaluate-compare-and-set loop, and an idempotent operator `release`. `AssetContentQuarantineRecordCodec` is a versioned, fail-closed, bounded text codec (hex-encoded free-text fields against delimiter injection) so the log works with any string-payload `DurableStateStore`, including `RoomDurableStateStore`, exactly as `AssetTransferSessionCodec` already does for sessions. A `DENY`-action match never touches the quarantine log, matching `Deny`'s "refused outright" semantics. **Verified locally (JVM, executed):** 28 new tests across 4 new classes (`AssetContentQuarantineLogTest` 11, `AssetContentQuarantineRecordCodecTest` 8, `HashDenyListAssetContentPolicyTest` 9 unit+engine-integration, `FileBackedAssetContentQuarantineTest` 1 jvmTest) plus the full pre-existing `dataloom-assets` JVM suite, all green, zero regressions. Persistence is checked directly against the real encoded payload string in the backing store's row (the same discipline `DurableAssetTransferSessionStoreTest` uses for its own sibling durable domain), and additionally against a genuine file on the real filesystem in `FileBackedAssetContentQuarantineTest` (a quarantine match through a real `FileAssetProvider` upload writes an actual file under a temp directory containing the matched digest, independently re-read by a fresh log instance simulating a process restart, with the upload's own committed path confirmed absent). **Revert-and-observe performed:** the deny-list lookup in `HashDenyListAssetContentPolicy.evaluate` was temporarily disabled and the suite re-run -- exactly the 6 tests whose outcome depends on a real match firing failed as expected, everything else (codec and log tests that do not depend on matching) stayed green, then the real lookup was restored and the full suite re-verified green. **Verified by cross-compilation only (Kotlin/Native, not executed -- no macOS host available):** `compileKotlinIosSimulatorArm64` and `compileTestKotlinIosSimulatorArm64` both succeed for the new commonMain/commonTest code (no Apple-specific source was added; everything here is common code, unlike the engine's own JVM/Android-only transform and file-provider slices).
