# Fragment: gate #97, Apple AES-256-GCM investigation (2026-10-01)

## (a) Proposed "Recently shipped" row

| 2026-10-01 | `#97`: investigated whether Apple AES-256-GCM (left undelivered by slice 3/ADR-0014 as a typed `TRANSFORM_UNSUPPORTED`) is reachable as a bounded slice, rather than re-implementing or re-asserting the prior summary. Went one level deeper than ADR-0014's one-line reason on all three realistic paths. **CommonCrypto cinterop**: directly confirmed (not just cited) that Kotlin/Native 2.4.10's `platform.CoreCrypto` binding is generated via `modules = CommonCrypto` — Apple's *public* `CommonCrypto` Clang module — and a `klib dump-metadata` of the actual bound package shows `CCCryptorCreateWithMode` exists but only `kCCModeECB/CBC/CFB/CTR/OFB/RC4/CFB8` are bound; `kCCModeGCM` and every `CCCryptorGCM*` function are absent with zero matches anywhere in the dump. This is Apple's own public header never declaring GCM, not a Kotlin/Native oversight; the only way to GCM through CommonCrypto is the private, ABI-unstable `CommonCryptorSPI.h`, rejected on security grounds for a core encryption primitive, not on effort grounds. **Swift/CryptoKit shim**: confirmed zero precedent for Kotlin/Native calling into Swift anywhere in this repo (`docs/apple/swift-interop.md` and all 5 existing `.swift` files are the opposite direction — Swift consuming the generated Kotlin framework); building the reverse bridge needs new Gradle build-system work invoking `swiftc`/`xcodebuild` plus macOS CI changes, and is not even compile-verifiable from Windows — `konan.properties` has Apple target-toolchains only for macOS hosts, none for `mingw_x64`. **Vendored third-party C AEAD**: mechanically closer (no Swift boundary) but still needs macOS to actually compile/link, and more importantly is a security-vendoring decision (trusting a third-party crypto implementation for the SDK's core confidentiality/integrity primitive) outside a single agent slice's authority — flagged explicitly rather than picked. No code changed: `AesGcmAssetChunkCipher`'s Apple `isSupported = false` / `AssetTransformUnsupportedException` behavior is untouched, matching this program's "bail honestly" precedent for genuinely blocked items. See `docs/apple/aes-gcm-investigation.md`. `#97` unchanged | `#97` investigation |
