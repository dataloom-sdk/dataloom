# Fragment: gate #97, file-backed asset transfer storage (2026-09-29)

## (a) Proposed "Recently shipped" row

| 2026-09-29 | `#97` slice 4 ([ADR-0016](../adr/ADR-0016-file-backed-asset-transfer-storage.md)): secure temp files, atomic promotion and cleanup (`FR-ASSET-009`), plus a real file-backed `AssetSource`/`AssetSink`/`AssetProvider`, for JVM/Android. `FileAssetSource` reads an existing file at random access; `FileAssetSink` stages a download in a secure temp file next to its destination and exposes `promote()` — additional API on the concrete class, since `AssetSink` predates a file-backed implementation — which atomically renames it onto the final path once the caller has confirmed `AssetTransferOutcome.Completed`, so the final path is never observable partially written. `FileAssetProvider` is a filesystem-backed sibling of `InMemoryAssetProvider` that assembles a completed upload's chunk files in bounded memory (one buffer, independent of asset size), verifies the whole-object digest exactly like the in-memory reference for an untransformed manifest, and promotes the assembled object onto a committed path with one atomic rename; it passes the same `AssetProviderContractKit` the in-memory provider does. Cleanup resolves ADR-0006's open decision 3 with two mechanisms: eager deletion of a session's temp files on `abortUpload` and on `completeUpload` (once its bytes live at the committed path), plus a bounded, host-driven `sweepAbandonedUploads(olderThan)` for sessions abandoned outright (client crashed, never called abort), using filesystem timestamps rather than in-memory state since a restarted process remembers neither. `FileAssetSink.read` tracks written byte *ranges* (bounded by chunk count, not asset size) rather than a per-byte bitmap, to return `-1` for an unwritten region the same way `InMemoryAssetSink` does without an O(asset size) memory cost. **Verified locally (JVM):** round trips through real files at and around chunk boundaries; a completed, not-yet-promoted download checked directly against the filesystem (nothing at the final path until `promote()`, the exact bytes there afterward with the temp file gone); `discard()` leaving nothing at either path; sparse-read semantics; the full provider contract kit (20+ scenarios) against `FileAssetProvider`; `abortUpload` and a tampered-whole-object-digest `completeUpload` each leaving nothing at the committed path and cleaning up temp files, checked directly against the filesystem; a completed upload's bytes appearing at the committed path in full; and `sweepAbandonedUploads` removing only sessions past its age threshold, leaving a fresh session alone, and making the swept session id subsequently report `SESSION_NOT_FOUND`. `dataloom-assets` still cross-compiles main and test for `iosArm64`/`iosSimulatorArm64`/`iosX64` unchanged (no common or Apple source touched); the JVM ABI baseline was regenerated for the three new public types, the Kotlin/Native baseline is byte-identical. **Not delivered:** an Apple (POSIX-based) equivalent of these three types — judged too large to fold into this PR alongside JVM/Android; see ADR-0016. **Not verified:** any Android instrumentation/emulator run (no Android-specific source set exists for this module to run one against) or any Apple execution. | `#97` |

## (b) Gate row percentage

`#97`: **35% -> 40%** (banded to 5%, a judgement). `FR-ASSET-009` is now implemented for JVM/Android with real, filesystem-verified atomic-promotion and cleanup behaviour, and a real (non-in-memory) provider exists that passes the same contract kit.
