# Fragment: gate #97, parallel asset chunk transfer (2026-10-01)

## (a) Proposed "Recently shipped" row

| 2026-10-01 | `#97`: parallel chunk transfer with concurrency limits and fairness (`FR-ASSET-006`). `AssetTransferEngine` gained one new constructor parameter, `maxConcurrency: Int = 1` — the smaller, additive change rather than a second engine class or a wider public-contract redesign, since the session-store layer (`AssetTransferSessionStore.applyEvent`'s compare-and-set retry loop) was already safe under concurrent `ChunkCommitted` writers and the three existing providers (`InMemoryAssetProvider`, JVM/Android `FileAssetProvider`, Apple `AppleFileAssetProvider`) were all already internally mutex-guarded and safe for concurrent chunk calls — confirmed by reading each, not assumed. `maxConcurrency = 1` (the default) is byte-for-byte the original sequential loop, untouched in behaviour; `> 1` runs a bounded worker pool — one coroutine per missing chunk index, gated by a `kotlinx.coroutines.sync.Semaphore` sized to `maxConcurrency` — draining the same missing-chunk list, each chunk allocating its own chunk-sized buffer rather than sharing one (bounded memory is now `maxConcurrency` chunk buffers, not one). **Fairness strategy**: `Semaphore` is documented ("Semaphore is fair and maintains a FIFO order of acquirers", verified against the actual `kotlinx-coroutines-core` 1.9.0 source this project depends on, not quoted from memory) to service waiters strictly FIFO, so no chunk can be starved behind others cutting in ahead of it. **Failure semantics**: this engine already stopped at the first chunk-level error without attempting further chunks in sequential mode (trivially "fail-fast" since nothing else was ever in flight); parallel mode preserves that exactly — the first chunk to report a terminal outcome cancels every other in-flight or queued chunk coroutine via ordinary structured-concurrency cancellation (`coroutineScope` cancelling its children when one throws), and that first outcome is returned, with no second failure policy introduced. No provider, `AssetSource`, or `AssetSink` implementation was modified. **Verified locally (JVM, executed):** the full `dataloom-assets` JVM test suite now numbers 231 tests across 17 classes, all passing — the 223 tests across the 15 pre-existing classes (including the 38-case `AssetTransferEngineTest`) pass unchanged, proving the default sequential path is unaffected, plus 8 new tests across 2 new classes: 7 concurrency-proof tests in `ParallelAssetTransferEngineTest` — genuine overlap via a self-releasing barrier that blocks until exactly `maxConcurrency` calls are concurrently in flight (not inferred from timing), the limit never exceeded (checked synchronously inside the probe, not just recorded), fail-fast cancellation of genuinely in-flight sibling chunks on one chunk's failure (for both upload and download) with the queued-but-never-started chunks confirmed never attempted, one slow/blocked chunk not starving the other concurrency slot's chunks to completion, and a full parallel upload-then-download byte-exact round trip; a mandatory negative control (`maxConcurrency = 1` against the same overlap-demanding probe) confirms the proof is real — it fails (times out against the barrier) exactly as a naive non-concurrent stub should; and 1 new integration round trip in `FileAssetProviderParallelTransferTest` against the real `FileAssetProvider` (not just the in-memory reference provider). **Verified by cross-compilation only (Kotlin/Native, not executed — no macOS host available):** `compileKotlinIosArm64`/`IosSimulatorArm64`/`IosX64` and their test equivalents succeed, including a new parallel-transfer round trip against the real `AppleFileAssetProvider` mirroring the JVM one; a macOS CI run is the first time any of it actually executes, same caveat the existing Apple file-backed provider work already carries. The Kotlin/Native ABI baseline (`api/dataloom-assets.klib.api`) and the JVM one (`api/dataloom-assets.api`) were regenerated together and both changed only in the one intended way (the new constructor parameter); `checkKotlinAbi` passes at module scope. | `#97` |
