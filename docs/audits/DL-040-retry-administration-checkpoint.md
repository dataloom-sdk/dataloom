# DL-040 retry administration checkpoint

## Scope

This checkpoint covers the common-code foundation for FR-RETRY-011 manual
retry/requeue and the administrative portion of FR-RETRY-012 authorized
reclassification.

## Implemented boundary

- stable command, principal, authorization, and bounded reason identities;
- immutable redacted original failure evidence;
- explicit `REQUEUE` and `RECLASSIFY_AND_REQUEUE` actions;
- host-owned authorization, durable compare-and-set state, and idempotent
  execution SPIs;
- fail-closed protected-category and recoverability enforcement;
- durable replay of success, denial, policy rejection, execution rejection, and
  execution failure;
- command-id conflict detection for changed immutable input;
- exact unconfirmed post-execution recording evidence;
- bounded contention and durable clock-regression rejection.

## Safety invariants

1. Automatic retry protection remains unchanged.
2. Authorization receives the complete immutable command and action.
3. Reclassification never overwrites the original failure snapshot.
4. No executor call occurs before durable authorized state exists.
5. The executor is idempotent by command id and validates canonical queue
   failure evidence before mutation.
6. A completed mutation plus failed final audit write is never collapsed into
   an ordinary failure or a new command.
7. Cancellation and unexpected exceptions propagate.
8. Stored failure evidence excludes payloads, credentials, headers, exception
   text, provider instances, and arbitrary metadata.

## Focused evidence

Common tests cover:

- safe recoverable requeue and durable replay;
- protected-category rejection without explicit reclassification;
- authorized reclassification with immutable original evidence;
- durable authorization denial;
- conflicting reuse of a command id;
- idempotent recovery after an unconfirmed terminal write; and
- clock regression before redelivery.

Additional local syntax and scenario verification covered executor rejection,
canonical failure snapshot recording, unexpected exception propagation, and
bounded persistent compare-and-set contention.

The external consumer probe compiles request construction and coordinator use
from outside the implementation modules. Exact JVM and Kotlin/Native ABI files
are generated by a one-time same-repository workflow and reviewed in the final
pull-request diff.

## Remaining DL-040 work

This checkpoint does not complete DL-040. Remaining administration work
includes:

- production durable stores for mandatory platforms;
- a queue-provider-specific executor with canonical target/failure validation;
- builder/facade and operational API assembly;
- role/permission integration beyond the host authorization SPI;
- administration events, bounded metrics, structured logs, tracing, and health;
- process-loss, multi-process, contention, and failure-injection qualification;
- end-to-end Book 2 `AC-FUNC-004` and complete V1 retry/circuit acceptance.
